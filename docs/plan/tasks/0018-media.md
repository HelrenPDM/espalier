## Goal
Authors put images, vector graphics and videos into lessons. A content pack
carries its media files in a `media/` folder next to its YAML and Markdown
files, and two new block kinds place them: `figure` shows an image or an SVG
with alternative text and a caption, and `video` plays a video with captions
and a transcript. A video comes from the pack, from an external file URL on an
allowlisted CDN host, or from the player of an allowlisted streaming service in
an iframe that loads only after the learner agrees. The platform keeps one media
library per installation. Authors upload files there, a background job converts
raster images to WebP and videos to WebM with VP9 and Opus, rebuilds every SVG
from an allowlist and checks every WebVTT file, and the library shows each file
with its state, facts and uses. Importing a pack moves its media into the
library; authors attach library files to workbench drafts. Pack export and
SCORM export write the converted files, so a pack stays self-contained and the
decision D18 holds: content packs stay the only import and export format.

## Scope
- In: The context `Espalier.Media` with the table `media_assets`, a content-addressed store below `MEDIA_DIR`, type and dimension detection from the file headers, the ffmpeg and ffprobe runner, the image, SVG, WebVTT and video processors, the optional ClamAV scan over a Unix socket, the Oban queues `media` and `media_video` with a stale sweep and a retention job, the library routes, and the route `GET /media/:file` that serves files to signed-in users with byte ranges.
- In: The pack format gains the folder `media/`, the block kinds `figure` and `video` with their attributes, and the validator rules for media references, alternative text, captions, transcripts and external URLs. The importer ingests the referenced media and checks external hosts against the allowlists of the installation, the publisher records the media per program in `program_media` and holds a publish back until every file is ready, and the diff compares them.
- In: `Payload`, `PackWriter`, `mix espalier.export`, the workbench (media entries in `pack_draft_media`, WebVTT files as text files, a staged download), and the SCORM export carry the media. The learner API resolves media into URLs, the CSP gains `media-src` and `frame-src` from operator allowlists, and the sign-out clears the HTTP cache of the browser.
- In: The player blocks `FigureBlock` and `VideoBlock` with the click-to-load notice for embeds, the media library page, the media entries of the workbench, the media state on the pack page, the demo pack media, the Dockerfile, compose, Makefile and nix changes, the ClamAV example, the guide `docs/guides/media.md`, and the updates of the guides of 0015, 0016, 0016a and 0017.
- Out: Audio-only blocks, HLS and DASH packaging or playback, adaptive bitrate ladders, live streaming, DRM, image editing (crop, resize by the author, annotations), video editing (trim, chapters), responsive image variants (`srcset`), automatic captions or transcripts, audio description tracks, HDR tone mapping, colour space conversion, object storage (S3) as a second store, resumable uploads, per-author quotas, and AVIF, HEIC, TIFF, BMP and RAW inputs. `Espalier.Media.Store` is the extension point for a second store.
- Out: Raw HTML in Markdown, inline Markdown images (`![alt](src)`), raster images embedded in an SVG, and media in other texts than lesson blocks (glossary, rules, items, policies, formats). The player records no playback data: no view, progress or completion event of a video reaches the server or the SCORM runtime, so `TRACKING_DETAIL` (README section 10) is unchanged.

4. **Store and limits.** `Espalier.Media.Store` owns every path below `MEDIA_DIR`:
   - Layout: `files/<aa>/<bb>/<sha256>.<ext>` for delivery files and posters, where `<aa>` and `<bb>` are the first four hex digits; `incoming/<asset id>` for a file that waits for processing; `work/<uuid>/` for the outputs of one job and for the staging directory of a draft download (step 16); `uploads/` for the temporary files of `Plug.Upload` (`PLUG_TMPDIR`, step 21). `root/0` returns `Path.expand(MEDIA_DIR)`, and `path/2`, `incoming_path/1`, `work_dir/1` and `staging_dir/0` build paths only from a lower-case hex digest of 64 characters, an extension of the closed list `webp`, `svg`, `webm` and `vtt`, or a UUID; each raises `ArgumentError` for anything else (ASVS 5.3.2).
   - `put/2` takes a finished file in a work directory and its extension, computes SHA-256 in blocks of 1 MiB with `:crypto.hash_init/1`, moves the file to its place with `File.rename/2` (the work directory lies on the same file system), keeps an existing file with the same digest and sets its modification time to now, sets mode 0640, and returns `{sha256, bytes}`. `remove/2` takes `pg_advisory_xact_lock(hashtext('espalier.media.files'))` in a transaction of its own, re-checks there that no asset names the digest in `sha256` or in `poster_sha256`, and deletes the file before that transaction commits; `ProcessWorker` (step 8) and the orphan sweep take the same lock, so a file that a new asset reuses is never deleted under it.
   - `accept_incoming/2` moves an upload or copies a pack file to `incoming/<asset id>`: `File.rename/2` when both lie on one file system, `File.cp/2` otherwise.
   - Fixed limits in `config :espalier, :media`, read through functions of `Espalier.Media`: `svg_max_bytes` 1,048,576; `captions_max_bytes` 524,288; `max_input_pixels` 40,000,000 (width times height of an image); `max_video_pixels` 8,294,400 (3840 times 2160 per frame); `max_frames` 1,000 for animated images; `image_timeout_seconds` 120; `video_timeout_factor` from step 1; `video_timeout_floor_seconds` 600; `max_pack_media` 500 media files per pack; `max_draft_media` 500 media entries per draft; `export_max_mb` 1,024 (step 17).
   - Quota: the used bytes are the sum of `bytes`, `poster_bytes` and `incoming_bytes` over all assets; a poster or delivery file that several assets share counts once per asset, which overstates the use. An ingest that would exceed `MEDIA_STORAGE_MAX_GB` answers `{:error, :storage_full}`, checked in the transaction of the ingest under `pg_advisory_xact_lock(hashtext('espalier.media'))`, so two concurrent ingests count one after the other. The quota covers the stored and the incoming files; uploads below `PLUG_TMPDIR`, job outputs and download staging need further space, which the guide names.
5. **Detection and the command runner.** `Espalier.Media.Sniff.detect(path, file_name)` reads the first 64 bytes for the signature and, for images, the header within the first 1 MiB (below), and returns `{:ok, %{kind, format, width, height, animated}}` or `{:error, :unsupported_type | :extension_mismatch | :too_many_pixels | :unsupported_animation}`:

   | Kind | Extensions | Signature | Format passed to ffmpeg |
   |---|---|---|---|
   | `image` | `.png` | `89 50 4E 47 0D 0A 1A 0A` | `apng` when the chunk walk meets `acTL` before the first `IDAT`, `png_pipe` otherwise |
   | `image` | `.jpg`, `.jpeg` | `FF D8 FF` | `jpeg_pipe` |
   | `image` | `.gif` | `GIF87a` or `GIF89a` | `gif` |
   | `image` | `.webp` | `RIFF`, four bytes, `WEBP` | `webp_pipe` |
   | `svg` | `.svg` | after an optional UTF-8 BOM and white space: `<?xml`, `<svg` or `<!--` | none |
   | `video` | `.mp4`, `.m4v`, `.mov` | `ftyp` at offset 4, and neither the major brand nor a compatible brand within the first 64 bytes is one of `mif1`, `mif2`, `msf1`, `heic`, `heix`, `heim`, `heis`, `hevc`, `hevx`, `hevm`, `hevs`, `avif`, `avis` or `avio` | `mov` |
   | `video` | `.webm`, `.mkv` | `1A 45 DF A3` | `matroska` |
   | `captions` | `.vtt` | after an optional UTF-8 BOM: `WEBVTT` followed by a space, a tab, a line break or the end | none |

   The extension is compared in lower case. A signature outside the table answers `unsupported_type`; an extension of another kind answers `extension_mismatch`.
   - Header dimensions: for images, `Sniff` reads width and height from the header before any process starts: the PNG `IHDR` (bytes 16 to 23), the GIF logical screen (bytes 6 to 9), the WebP `VP8 `, `VP8L` or `VP8X` header, and the first JPEG `SOFn` segment found by a walk over the segment markers within the first 1 MiB. Width times height above `max_input_pixels` answers `too_many_pixels`. For a PNG it walks the chunk headers (length and type, skipping the data with `:file.position/2`) from offset 8 until `acTL` or `IDAT`, at most 64 chunks or 1 MiB, and a length above 2^31 - 1 answers `unsupported_type`. A WebP whose `VP8X` flags (byte 20) carry the animation bit 0x02 is `animated`; on a build without an animated WebP decoder (step 1) it answers `unsupported_animation`.
   - `Espalier.Media.Command.run(executable, args, opts)` opens `Port.open({:spawn_executable, timeout_path}, [:binary, :exit_status, :stderr_to_stdout, :use_stdio, {:args, ["--kill-after=10", seconds, executable | args]}, {:cd, work_dir}])`, collects at most 1 MiB of output (the rest is counted and dropped), passes `out_time_us=` lines of `-progress pipe:1` to an `on_progress` callback, and returns `{:ok, output}` for exit status 0, `{:error, :timeout}` for status 124 (the deadline) or 137 (the kill ten seconds later), and `{:error, {:exit, status, tail}}` with the last 20 lines (each at most 300 characters) otherwise. A crash of the BEAM leaves an ffmpeg running at most until that deadline. The arguments are a list built by `Espalier.Media.Ffmpeg`; a filter expression such as `scale=-2:'min(ih,1080)'` is one list element, and its quotes belong to the filtergraph syntax of ffmpeg. No shell reads the arguments. A test asserts that no function of that module puts a title, a file name or another string from a request into the arguments (ASVS 1.2.5).
   - Every ffmpeg call starts with `-nostdin -hide_banner -loglevel error -max_alloc 536870912 -filter_threads <N>`, gives its input as `-threads <N> -protocol_whitelist file -f <format> -i <path>`, and repeats `-threads <N>` among the output options before an explicit output format (`-f webp` or `-f webm`) and the output path (N = `MEDIA_FFMPEG_THREADS`). Image inputs add `-max_pixels <max_input_pixels>` and video inputs `-max_pixels <max_video_pixels>` before `-i`, and `mov` inputs add `-enable_drefs 0`.
   - Every ffprobe call is `ffprobe -v error -max_alloc 536870912 -threads <N> -protocol_whitelist file -f <format> -max_pixels <limit> -count_packets -show_entries stream=index,codec_type,codec_name,width,height,pix_fmt,nb_read_packets,duration:stream_tags=alpha_mode:format=duration,nb_streams -of json -o <work dir>/probe.json <path>`. `Jason.decode/1` reads `probe.json` (numbers such as `nb_read_packets` arrive as decimal strings), so log lines in the merged output cannot spoil the JSON; the merged output serves the error tail and the recognition of the max-pixel message, which answers `too_many_pixels`. A missing or undecodable `probe.json` answers `conversion_failed`.
   - `Ffmpeg.check/0` (step 2) runs at boot in prod and in the test of the module.
6. **Processors.** Each processor takes the incoming file and the detected format, writes into a work directory, and returns the facts of the asset or a failure code of step 8: for a video from a probe of the delivery file, for an image from the WebP header of its delivery file.
   - Images: the probe gives the frame count (`nb_read_packets`; absent counts as one) and the pixel format. A still image converts with `-frames:v 1 -map_metadata -1 -vf scale='min(iw,E)':'min(ih,E)':force_original_aspect_ratio=decrease` (E = `MEDIA_IMAGE_MAX_EDGE`) and `-f webp`: `-c:v libwebp -lossless 1 -compression_level 6` for PNG and GIF inputs and for WebP inputs with a `VP8L` chunk, `-c:v libwebp -quality 82` for JPEG inputs and lossy WebP inputs. An animated input (a GIF or an APNG with more than one frame) with at most `max_frames` frames converts with `-map_metadata -1 -vf scale='min(iw,E)':'min(ih,E)':force_original_aspect_ratio=decrease -c:v libwebp_anim -loop 0 -quality 80 -f webp`, and its poster is its first frame, converted with the same filter and `-c:v libwebp -quality 80`; more frames answer `too_many_frames`. Width, height and `has_alpha` come from the WebP header of the delivery file, which `Sniff` parses: the frame size of a `VP8 ` chunk, the size and the `alpha_is_used` bit of a `VP8L` chunk, or the canvas size of a `VP8X` chunk with an `ALPH` chunk for alpha, because ffprobe 8.1.2 reports `argb` for every lossless WebP and no size for an animated one. An animated image takes `has_alpha` from its poster, because `libwebp_anim` sets the alpha flag of `VP8X` also for an opaque source. `animated` follows from the frame count of the input probe. The orientation result of step 1 decides the `transpose` filter.
   - SVG: `Espalier.Media.Svg.sanitize(binary)` rejects a file above `svg_max_bytes`, a file that is no UTF-8, a `DOCTYPE`, an entity declaration and a processing instruction other than the XML declaration, and parses the rest with `:xmerl_sax_parser.stream/2` and the options `disallow_entities` and `skip_external_dtd`. It writes a new document from the events. The element allowlist is `tags.svg` plus `tags.svgFilters` of DOMPurify 3 plus `use`, which DOMPurify lists in `svgDisallowed` and this task admits with an internal reference only (below), and the attribute allowlist `attrs.svg` plus `attrs.xml` (the release current at implementation, named in the module documentation), each name written in its case-sensitive SVG 1.1 spelling (`clipPath`, `linearGradient`, `radialGradient`, `textPath`, `viewBox`, `preserveAspectRatio`, `gradientUnits`, `stdDeviation`), compared exactly. The allowlist omits `script`, `foreignObject`, `iframe`, every animation element (`animate`, `animateColor`, `animateMotion`, `animateTransform`, `set`) with `mpath`, and `metadata`; `a` is unwrapped (its children stay); every element outside the SVG namespace and every attribute that is neither unprefixed nor one of the `xlink:` and `xml:` names of `attrs.xml`, such as `sodipodi:*` and `inkscape:*`, is dropped; every attribute whose name starts with `on` is dropped. `use` stays with an `href` or `xlink:href` of `#<id>` only, because the player shows SVG files only through `<img>` and the media route serves them with a `sandbox` CSP; every other `href` and `xlink:href` is dropped. An `image` element rejects the file, because a raster embedded in an SVG would keep its metadata and pass an unconverted decoder input to the browsers. In every attribute value, every `style` attribute and every `style` element, a `url(` other than `url(#<id>)`, `@import`, `expression(`, `image-set(`, `-webkit-image-set(`, `image(`, `cross-fade(`, `element(`, `src(` and a backslash reject the file, and so do an `@keyframes` rule and the properties `animation`, `animation-*`, `transition` and `transition-*`, so an SVG never moves. Text and attribute values are escaped as `Espalier.Interop.xml_escape/1` does. The root must be `svg` in the SVG namespace, and `viewBox` or `width` and `height` give the facts. A rejection answers `invalid_svg` with the reason tag `too_large`, `encoding`, `doctype`, `entity`, `processing_instruction`, `parse_error`, `root`, `embedded_image`, `css` or `animation` in `failure_detail`. A second sanitize of the output gives the same bytes, which a property test checks.
   - Captions: `Espalier.Media.WebVtt.check(binary)` rejects a file above `captions_max_bytes`, no UTF-8, a U+0000, a missing `WEBVTT` header, more than 10,000 cues, a cue timing line that does not parse (`hh:mm:ss.ttt` or `mm:ss.ttt`, start before end), and a `STYLE` block. It stores the bytes unchanged; `duration_ms` is the end of the last cue. A failure answers `invalid_captions` with the reason tag `too_large`, `encoding`, `nul`, `header`, `too_many_cues`, `timing` or `style` in `failure_detail`.
   - Video: the probe gives the streams. No video stream answers `no_video_stream`; a duration above `MEDIA_VIDEO_MAX_MINUTES` answers `too_long`; width times height above `max_video_pixels` answers `too_many_pixels`. A Matroska input whose first video stream is `vp9` with the pixel format `yuv420p` and without the stream tag `alpha_mode`, whose first audio stream is absent or `opus`, and whose height is at most `MEDIA_VIDEO_MAX_HEIGHT` is remuxed without a new encoding: `-map 0:v:0 -map 0:a:0? -c copy -map_metadata -1 -map_chapters -1 -f webm`. The remux passes the VP9 and Opus streams of the upload unchanged to the browsers, which decode them as they decode every WebM. Every other input, VP8, AV1, Vorbis, other pixel formats and VP9 with alpha included, is converted, and `-pix_fmt yuv420p` drops an alpha channel, which the guide states: `-map 0:v:0 -map 0:a:0? -sn -dn -map_metadata -1 -map_chapters -1 -c:v libvpx-vp9 -b:v 0 -crf 32 -deadline good -cpu-used 4 -row-mt 1 -g 240 -pix_fmt yuv420p -vf scale=-2:'min(ih,H)' -c:a libopus -b:a 96k -ac 2 -f webm -progress pipe:1 -nostats` (H = `MEDIA_VIDEO_MAX_HEIGHT`). ffmpeg applies the rotation of the input while it converts. The poster is the frame at `min(1 s, duration / 10)` of the delivery file, converted with `-frames:v 1 -map_metadata -1 -c:v libwebp -quality 80 -f webp` and no scale filter, so it has the size of the video. Width, height, duration and `has_audio` come from a probe of the delivery file. The deadline of the conversion is `max(video_timeout_floor_seconds, video_timeout_factor * duration)` (step 8); progress updates `progress` at most once per two seconds. HDR inputs convert without tone mapping, which the guide states.
7. **Malware scan.** `Espalier.Media.Clamd.scan(path)` runs only with `MEDIA_CLAMAV_SOCKET`. It connects with `:gen_tcp.connect({:local, socket}, 0, [:binary, active: false, packet: :raw], 5_000)`, sends `zINSTREAM\0`, then the file in chunks of 1 MiB, each prefixed with its length as a 32-bit big-endian integer, then four zero bytes, and reads the reply up to a NUL byte (at most 1 KiB) with a timeout of 60 seconds plus one second per 10 MiB. `stream: OK` returns `:clean`; `stream: Heuristics.Limits.Exceeded.<limit> FOUND` returns `{:error, {:limits_exceeded, limit}}`; another `stream: <signature> FOUND` returns `{:found, signature}`; every other reply, among them `INSTREAM size limit exceeded`, a closed socket, a timeout and every failure of the connect, an exit of `:gen_tcp.connect/4` included, return `{:error, reason}`. The scan reads the incoming file before ffprobe, xmerl or the WebVTT check touch it.
   - A finding fails the asset with `malware_found`, deletes the incoming file, and logs the security event `upload_validation` (OWASP logging vocabulary) with `user_id` (the uploader or `nil`) and `reason` set to `malware_found:` and the signature name, cut to 100 characters with every character outside `[A-Za-z0-9._-]` replaced by `_`. Add `upload_validation` to `@events` and `@warnings` of `Espalier.SecurityLog`, extend the vocabulary pattern of `test/espalier/security_log_test.exs` with the prefix `upload`, and add a row and a paragraph to `docs/security/logging.md`.
   - Every error fails the asset with `scan_failed` (the scan fails closed) and the reason tag `limits_exceeded`, `size_limit`, `timeout`, `closed`, `connect` or `reply` in `failure_detail`, and `Logger.error/2` names the asset id and the reason tag.
   - The clamd limits `StreamMaxLength`, `MaxFileSize` and `MaxScanSize` cover `MEDIA_VIDEO_MAX_MB`, which may not exceed 2047 with a scanner (step 2), `MaxScanTime` covers the scan of the largest file, and `AlertExceedsMax yes` turns every exceeded limit into a `Heuristics.Limits.Exceeded` reply, so a file that clamd did not scan completely fails with `scan_failed`. `docs/guides/examples/clamd.conf` (step 21) sets these values, and the guide names the rule.
8. **Context and workers.** The public functions of `Espalier.Media` take the scope first and return `{:error, :forbidden}` for a scope without the role `author`.
   - `ingest(scope, %{path, file_name}, opts)` serves the library upload with `origin: :upload`. `ingest_pack_file(%{path, file_name}, actor_id)` serves the importer with `origin: :pack`; it runs no role check, because `Catalog.import_pack/3` has checked the role of the author and `mix espalier.import` and the release functions run as the operator, sets `created_by_id` to `actor_id` or `nil`, and writes no audit event. Both detect the file (step 5), apply the size limit of its kind (`MEDIA_IMAGE_MAX_MB` for images, `svg_max_bytes`, `captions_max_bytes`, `MEDIA_VIDEO_MAX_MB`; above it `{:error, :media_too_large}`), compute SHA-256 of the source, generate the asset id, and place the file at `incoming/<id>` with `accept_incoming/2` before any transaction, so a long copy holds no lock. Then, in one `Repo.transact/1` under the lock of step 4: an asset whose `source_sha256` equals the digest, or else the oldest `ready` asset whose `sha256` equals it, selected `FOR UPDATE` so that the lookup waits for a running deletion and then finds no row, is returned with `:existing`, its `updated_at` set to now unless it is in `processing`, and for an upload its `origin` set to `upload`, and the placed copy is deleted; a `failed` asset found this way is reset to `queued` with the placed copy, a quota check and a new job. Otherwise the quota is checked, the asset is inserted as `queued` with `title` (the file name without its extension, cut to 255 characters, U+0000 removed), `source_name`, `incoming_bytes` and `created_by_id`, the job `Espalier.Media.ProcessWorker` is inserted (queue `media_video` for videos, `media` otherwise), and an upload writes the audit event `media.uploaded` with `%{kind}`. An error deletes the placed copy. Returns `{:ok, asset, :created | :existing}`. The match on `sha256` lets a pack written by `mix espalier.export` import into the same assets on the same installation.
   - `ProcessWorker` (`max_attempts: 1`) moves the asset from `queued` to `processing` with a conditional `update_all`, and exits `:ok` when no row changed, so a job that finds its asset taken, done or failed does nothing. It scans (step 7), runs the processor of the kind (step 6), computes the digests, and then moves the delivery file and the poster into the store and sets `ready` with digests, sizes and facts, `incoming_bytes` 0 and `progress` 100 in one transaction under the file lock of step 4, then removes the incoming file and the work directory. A failure sets `failed` with its code and reason tag and `incoming_bytes` 0, removes both, and logs as step 7 states. The failure codes are `too_many_pixels`, `too_many_frames`, `too_long`, `no_video_stream`, `unsupported_animation`, `invalid_svg`, `invalid_captions`, `malware_found`, `scan_failed`, `conversion_failed`, `timeout` and `interrupted`. Each job has one deadline for all its commands after the scan, and every `Command.run/3` receives the remaining time: `image_timeout_seconds` for an image, SVG or captions job, and `max(video_timeout_floor_seconds, video_timeout_factor * duration) + image_timeout_seconds` (the conversion and the poster) for a video job. `timeout/1` of the job is the largest such deadline of its kind (with `MEDIA_VIDEO_MAX_MINUTES` for the duration of a video) plus the scan timeout of the size limit of the kind (step 7) plus 60 seconds, so `Command` answers `{:error, :timeout}` first and the worker records `timeout`.
   - `process_now(asset)` runs the same steps in the calling process for an asset in `queued`. `Report.run_import/2`, used by `mix espalier.import`, `Espalier.Release.import_pack/2` and `seed_demo/1`, calls it for every `queued` asset of `payload["media"]` before it publishes, because these paths run Oban with `queues: false, plugins: false`. A server that runs next to them may take a job first, so `run_import/2` then waits, with a deadline of the largest job timeout of these assets, until every asset is `ready` or `failed`, and publishes through `Publisher.publish/1`, whose media gate (step 10) holds back an import with a failed asset. With `--draft` the jobs stay queued for the running server. `Espalier.Release.import_pack/2` calls `start_app/0` in place of `load_app/0`, as `seed_demo/1` does, so the job insert of an ingest finds a running Oban instance; its documentation changes accordingly.
   - `StaleWorker` (queue `default`, every 15 minutes) fails with `interrupted` every asset in `processing` whose `updated_at` lies longer ago than twice its job timeout and at least one hour, and logs each one through `Logger.error/2` with the asset id and the failure code; removes every entry of `incoming/` and `work/` whose modification time lies more than one hour back and that no asset in `queued` or `processing` names (download staging included); removes every stored file older than one hour whose digest no asset names in `sha256` or `poster_sha256`, which a crash between `put/2` and the row update can leave, under the file lock of step 4; and removes every file below `uploads/` whose modification time lies more than one hour back and every empty `plug-*` directory there, which `Plug.Upload` leaves after a crash.
   - `RetentionWorker` (queue `default`, daily) selects each asset of origin `pack` that has not been updated for `unused_days`, locks it with `FOR UPDATE`, re-checks its uses (programs, drafts and validated imports) and `updated_at` in the same transaction, deletes it when it is unused, and removes its files after the commit. Assets of origin `upload` stay until an author deletes them.
   - Uses: `uses(asset)` returns the published programs from `program_media`, the drafts from `pack_draft_media`, and the imports in status `validated` whose `media_asset_ids` contain the asset id (`^id = ANY(media_asset_ids)`, step 3); the `unused` filter of `list_assets/2` uses the same conditions in one `NOT EXISTS` subquery. Programs and drafts block a deletion; validated imports do not, and an import that lost an asset cannot be published (step 10). A payload without the key `media`, such as one validated before this task, holds no media.
   - Library functions: `list_assets(scope, filters)` with `kind`, `status`, `unused` (boolean), `q` (case-insensitive part of the title), `limit` (1 to 100, default 50) and `after` (an opaque cursor over `inserted_at` and `id`, newest first); `get_asset(scope, id)` with its uses; `update_asset(scope, id, attrs)` (title); `delete_asset(scope, id)`, which locks the row with `FOR UPDATE`, answers `{:error, {:asset_in_use, uses}}` while a program or a draft uses it, and otherwise deletes the row, writes the audit event `media.deleted` with `%{kind}` in the same transaction, and removes the files after the commit through `Store.remove/2`.
   - `docs/security/logging.md`, the audit page (`KNOWN_ACTIONS` in `frontend/src/admin/audit/AuditPage.tsx`) and its test name `media.uploaded` and `media.deleted`.
9. **Pack format.** `Espalier.Catalog.Pack.MediaPath.check(path)` first applies the general rules of `Espalier.Workbench.Paths` (valid UTF-8 of 1 to 527 bytes, components of at most 255 bytes, no U+0000, no backslash, not absolute, no empty, `.` or `..` component), which move into the public function `Paths.general?/1`, and then accepts `media/` followed by zero to three directories and a file name, each directory satisfying `Schema.Cast.key?/1` and the file name `<key>.<ext>` with a key of that format and one of the lower-case extensions of step 5. `kind/1` maps the extension to its kind, and `delivery_path/1` replaces the extension by the delivery extension of the kind (`webp` for images, `svg`, `webm`, `vtt`).
   - Loader: the walk keeps every regular file below `media/` in `loaded.media` as `%{path, file, bytes}` (the absolute path and the size of `File.lstat/1`) without reading it. A path that fails `MediaPath.check/1`, a size above the limit of its kind, and more than `max_pack_media` files are errors at their path. A directory `modules/media/` stays a module directory, as before. Files outside `media/` and the layout stay ignored.
   - Directives: `@kinds` gains `figure` and `video`, and `@attributes` gains `src`, `alt`, `decorative`, `size`, `title`, `poster`, `captions` and `embed`. The rule for `key` becomes a table of the attributes each kind admits: every kind admits `provenance`, `collapsed_on` and `cite`; `placeholder` adds `key`; `figure` adds `src`, `alt`, `decorative` and `size`; `video` adds `src`, `embed`, `title`, `poster` and `captions`. Another attribute answers `attribute <name> is allowed on <kinds> blocks only`. The block map gains `media`, a string-keyed map for the two new kinds and `nil` otherwise.
   - Validator: `Validator.cast_block/2` passes `nil` for an empty body of a `figure` or a `video`, `Schema.Block` requires `body` for every other kind only, and the normalizer writes `""` for it, so the body of a `figure` (the caption) and of a `video` (the transcript) may be empty while `Schema.Cast` keeps rejecting empty strings elsewhere. `Schema.Block` validates `media` with an embedded schema per kind. `figure`: `src` required, a `media/` path of an image or an SVG; `alt` 1 to 1,000 characters, required unless `decorative=true`, and absent with it; `decorative` only `true`; `size` one of `small`, `medium`, `full` (default `full`). `video`: exactly one of `src` and `embed`; `src` a `media/` path of a video, or an absolute URL with the scheme `https`, a host, no user info, at most 2,000 characters and a path that ends in `.webm` or `.mp4` (an `.m3u8` or `.mpd` path answers `streams need an embed player: use embed`); `embed` an absolute `https` URL of at most 2,000 characters without user info; `title` required, 1 to 255 characters; `poster` a `media/` path of an image, not with `embed`; `captions` 1 to 8 entries `<media path>:<language>` separated by commas, each a `.vtt` path and a BCP 47 tag (`~r/\A[a-z]{2,3}(-[A-Za-z0-9]{2,8})*\z/`), languages distinct, not with `embed` (`captions need a video file: use src`). A video with `src` needs `captions` or a non-empty body (the transcript), and a video with `embed` needs a non-empty body. This is the minimum that the validator can check; WCAG 2.2 also asks for captions of every video with audio (1.2.2), a text alternative that describes the picture as well as the sound (a descriptive transcript) or an audio description (1.2.3) and an audio description where the picture carries information that the audio does not (1.2.5), which `docs/guides/media.md` states as the task of the author. Every `media/` reference must name a file of `loaded.media` with an extension of the required kind. A block body that holds the Markdown image syntax (`~r/!\[[^\]]*\]\(/`) answers `use a figure block for images`. All findings are errors with the line of the block, so the property of 0008 holds that only the alignment checks give warnings.
   - Normalizer: the block gains `"media"`: for `figure` `%{"src", "alt", "decorative", "size"}`, for `video` `%{"src", "embed", "title", "poster", "captions" => [%{"src", "lang"}]}`, every key present with `nil` for an absent value, and `nil` for the other kinds. The payload gains no media list here; step 10 adds it.

## Notes
- The maintainer chose on 2026-10-15: specification first, the library together with a `media/` folder in packs, conversion on the server with ffmpeg to WebM with VP9 and Opus, and an optional ClamAV scan with a recorded deviation without it (README section 15, decision D19). The scan uses a Unix socket of a container on the same host, which needs no TLS, so the row 12.3.1 gains no further deviation.
- Delivery formats keep a pack self-contained: an export writes the converted files, and a second installation imports them. On the same installation the delivery digest finds the existing asset. On another installation the importer converts the files again: a lossless WebP keeps its pixels, a lossy WebP is encoded again at quality 82 on each import into another installation, an SVG and a WebVTT file stay byte for byte, and a WebM that meets the remux rule of step 6 is remuxed without a new encoding. Originals are not kept; an author who needs an original keeps it in the repository of the organization.
- Every uploaded raster image is converted to WebP, because the conversion removes metadata (EXIF location, camera serial numbers) and any data that a file carries beyond its pixels, and one delivery format per kind serves the player and the SCORM package alike. The guide names the Safari releases that play WebM with VP9 and Opus, from caniuse at the spike.
- A video with an external `src` loads nothing until the learner presses play (`preload="none"`), so it needs no notice of its own; an embed loads the player of another organization with the page, so it waits for the learner by default. Both defaults follow the data-sparing settings of README section 10.
- The ffmpeg package of Debian is built with GPL components. The image runs it as a separate program and links none of it, and the Apache-2.0 code stays unaffected; `NOTICE` and `docs/guides/security.md` name the package, whose source Debian publishes.
- `Archive` reads a pack upload into memory up to `PACK_UPLOAD_MAX_MB`, while a library upload streams to disk, so the guide recommends the library or an external URL for videos above that limit.
- Block ids of the standalone and SCORM runtimes count the blocks of a lesson, so a media block added before an explanation changes the fingerprint of the suspend data of a package that was exported before (0016); a learner of the new package starts that module again.
