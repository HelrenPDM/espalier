## Goal
Organizations maintain policies with versions and an approved tool list,
learners acknowledge policy versions, facilitators issue attendance
certificates, which also provide evidence for the learning objectives of their
format, and the platform issues credentials when requirements are met,
moves them through refresher and expiry, and reports them to downstream systems.

### Credentials
10. `Espalier.Credentials.evaluate(scope, program)` replaces the stub `evaluate/2` of 0009 step 14 and keeps its return shape `{:ok, changed}`:
    - It loads the qualifications of the program that carry no `archived_at`, with their requirements, and checks each requirement for `scope.user`: `module_completed` against `module_completions`, `assessment_passed` against a passed attempt, `policy_acknowledged` against the current version of the policy key, `attendance` against certificates for the format key when that format has `attendance_counts: true`, and `qualification_held` against a credential in force. A credential is in force while its status is `active` or `refresh_due`.
    - When every requirement holds and the user has no credential for the qualification, it issues one with the status `active`, `unlocks_snapshot` copied from `Qualification.unlocks`, `issued_at` now, and `valid_until` set to the issue date plus `validity_months` for `validity_kind: months` and to `nil` otherwise. A revoked credential blocks a new issue for its qualification.
    - It restores a `refresh_due` or `expired` credential to `active` when the refresher mode of the qualification holds after `refresh_due_at`. `update_unit` needs a completion of the module flagged `refresher_unit` later than `refresh_due_at`. `full_run` needs every requirement met again: module completions and passed attempts later than `refresh_due_at`, certificates with `held_on` on or after its date, an acknowledgement of the current version of each required policy, and each required qualification in force. `test_only` needs a passed attempt, later than `refresh_due_at`, at the exam of each `assessment_passed` requirement. A restore sets `valid_until` as an issue does, counted from the restore date, keeps `unlocks_snapshot` and clears `refresh_due_at`.
    - Each issue and each restore enqueues the webhook event `credential.issued`. The function returns the changed credentials.

    0009 calls it after a passed attempt and after a module completion. This task also calls it after an acknowledgement (step 8) and after an attendance certificate (step 16).

## Notes
- The credential states and transitions are those of `credential-lifecycle.puml`: an issue leads to `active`; `active` moves to `refresh_due` through the notice period or a policy version; `refresh_due` and `expired` return to `active` through the refresher; `refresh_due` moves to `expired` after the grace period; and every state except `revoked` moves to `revoked` through an admin. The tests of step 24 cover each transition.
- `unlocks_snapshot` keeps what the credential permitted when it was issued, even if a later pack version changes `Qualification.unlocks`.
- A restore sends `credential.issued` again with the new `valid_until`. README section 11 names four events, and a downstream system that grants the unlocked tasks on `credential.issued` thereby learns that the credential is in force again.
- The integration API and the requirement kind `qualification_held` count a credential in `refresh_due` as in force, because its holder keeps it until the grace period ends (`credential-lifecycle.puml`). Each entry of the integration API carries its `status`, so a downstream system can tell `active` from `refresh_due`.
- An attendance certificate is the only record of this task that the objective status reads. 0009 derives the status per request from exam attempts, attendance certificates and, with `TRACKING_DETAIL=standard`, item responses. With `attended_format_ids/2` of step 10 in place, the objectives `m1-self-own-responsibility` and `m1-social-team-transparency` of the demo pack, whose only evidence is the format `workshop`, can reach `evidenced` on the platform.
